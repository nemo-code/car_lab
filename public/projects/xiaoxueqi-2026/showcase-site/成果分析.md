# 智能网联实验室小学期成果分析

整理日期：2026 年 9 月 21 日
资料范围：当前文件夹下 9 个小组提交的报告、汇报 PPT、项目源码/压缩包和演示视频。

## 1. 总体观察

当前资料可以归纳为三条实践路线：

| 路线 | 小组 | 主要能力 | 展示重点 |
|---|---|---|---|
| 硬件实物 | 硬件一至五组 | STM32/51、传感器、电机、PWM、PID、嵌入式视觉 | 设备真的能动、能循迹、能避障、能完成场景任务 |
| 软件系统 | 软件一至三组 | Android/Compose、CAN、SocketCAN、AIDL、CameraX、ML Kit、TTS | 数据被实时读出、分析、告警并形成座舱体验 |
| 仿真交互 | 游戏组 | Unity、C#、Photon、车辆动力学、多人联机 | 把驾驶和座舱能力包装成可玩的多人体验 |

材料统计：9 个 PPTX、41 个 DOCX、9 个 MP4，以及 4 个源码/工程压缩包。这个结构说明本次展示既有“实物运行”的证据，也有“软件链路”和“项目过程”的文档依据。

## 2. 分组分析

### 硬件一组｜智能循迹小车

核心贡献是把电源、驱动、编码器、8 路灰度传感器和双闭环控制串成一套完整小车系统。项目适合展示“从电路到控制算法”的完整链路，特别适合在招新页面中作为硬件入门代表。

**展示建议：** 用 10～15 秒视频突出“启动—识别黑线—稳定转弯—OLED 显示状态”四个镜头；网页详情中列出 TB6612、MG513、灰度传感器和 PID，能让观众快速理解技术含量。

### 硬件二组｜普中 51 红外循迹小车

项目完成了按键运动控制和红外循迹，是最容易被现场观众理解和复现的一类作品。它的优势不是技术栈最复杂，而是演示路径清晰、反馈直接，适合作为“第一次接触嵌入式”的体验入口。

**展示建议：** 把“按键前进后退左转右转”和“自动循迹”分成两个视频入口，突出从手动控制到传感器闭环的学习进阶。

### 硬件三组｜STM32 智能小车

项目同时覆盖超声波避障、红外循迹和蓝牙遥控，形成了“感知—决策—执行—通信”的完整模块结构。报告中还给出了误差和延迟等指标，适合在网站上作为硬件项目的技术标杆。

**展示建议：** 使用“避障 / 循迹 / 蓝牙”三标签切换，配合 0.7 cm 测距误差、约 120 ms 蓝牙响应等量化结果，增强可信度。

### 硬件四组｜避障与红外循迹系统

项目聚焦 STM32 小车的避障与红外循迹能力，适合突出“整车装配、底层驱动、现场联调”的实践过程。它和硬件三组形成互补：一个更强调多模块与指标，另一个更强调从零完成整车闭环。

**展示建议：** 采用“问题—方案—现场效果”的叙事：障碍物出现 → 传感器感知 → 控制策略决策 → 小车绕行/循迹。

### 硬件五组｜果实成熟度智能监测与采摘决策

这是硬件方向中最具场景化和跨学科特征的项目，把树莓派、机器视觉和农业任务结合起来。项目很适合在招新海报中承担“智能技术不只服务汽车，也能进入真实生产”的传播作用。

**展示建议：** 将“成熟度识别”和“采摘决策”拆成两个画面，用一句话解释识别结果如何影响动作选择，降低非技术观众的理解门槛。

### 软件一组｜HelloCar 车载沙盘 App

项目特点是把真实 CAN 数据、TCP JSON Lines、车辆诊断、报警中心、360 全景和企业演示模式组合成一个完整的车载沙盘。尤其是对真实数据与教学仿真数据进行区分并标注来源，这一点很适合在网站中作为“工程边界意识”的亮点。

**展示建议：** 网页详情优先展示“首页状态—诊断记录—报警中心—企业演示”四个页面；资料索引保留 PPT、报告和工程压缩包，便于后续答辩或复盘。

### 软件二组｜Smart Copilot 智能驾驶辅助

项目聚焦驾驶员状态感知与主动安全：CAN 车辆状态、CameraX、ML Kit、PERCLOS、超速提醒、行程统计和 TTS 语音播报形成一条完整链路。它是软件方向中最适合对外讲述“智能驾驶辅助”价值的作品。

**展示建议：** 用三步卡片呈现：采集车辆与人脸数据 → 判断疲劳/超速 → 触发界面与语音告警；避免只堆技术名词。

### 软件三组｜HELLOCAR 车载智能驾驶辅助系统

项目进一步下沉到 Android + Compose、NDK + SocketCAN、can0 真实 CAN 帧、CameraX 和 ML Kit，突出“真实车载数据链路 + 多源交互”的工程能力。它与软件二组的差异是底层数据通道更深入，更适合展示系统架构和底层接口。

**展示建议：** 展示一张系统架构图，明确 UI 层、状态层、数据层；再用一个真实数据字段例子说明 CAN 帧如何变成车速/挡位/电量等可读状态。

### 游戏组｜驰界回响模拟驾驶游戏

项目使用 Unity 和 Photon PUN 2，把车辆动力学、方向盘输入、多人房间、实时聊天、驾驶舱视角、HUD、音乐电台和昼夜切换组合成完整的沉浸式体验。它是成果展中最适合作为“吸引观众停留”的入口。

**展示建议：** 首屏卡片突出“多人联机 + 座舱娱乐”，详情页再展开车辆控制、房间管理、实时聊天、摄像机和 HUD，形成由体验到技术的渐进叙事。

## 3. 网站展示策略

1. **首屏先讲价值，不先讲文件。** 用“把车造出来，把想法开上路”作为统一主题，先让新生知道实验室做的是能跑、能玩、能展示的东西。
2. **按方向筛选，按项目深入。** 网站提供硬件实物、软件系统、仿真交互三个筛选入口；每个项目详情包含摘要、亮点、技术栈、成员、图片、视频和资料索引。
3. **用真实证据建立可信度。** 9 段视频、PPT、报告与工程压缩包都保留可访问入口；不要只展示宣传语。
4. **把技术词翻译成体验。** 例如将“PERCLOS”解释为“连续闭眼比例，用于判断疲劳”，将“SocketCAN”放在“真实 CAN 数据链路”之后，先讲懂再讲深。
5. **招新内容和成果内容打通。** 海报上的四句话——小车循迹、车机读 CAN、相机发现疲劳、多人一起开——分别对应网站中的项目卡片，扫码后可以直接看到同类成果。

## 4. 招新传播建议

- **主标题：** 下一台车，等你来造。
- **副标题：** 从一根线、一行代码、一张界面开始，把想法做成能跑、能玩、能展示的作品。
- **适合吸引的学生：** 对嵌入式、Android、机器视觉、Unity、机器人、智能驾驶、交互设计感兴趣的同学。
- **海报落点：** 二维码旁边明确写“扫码加入钉钉群”，同时保留“招新 / 交流 / 项目协作 / 成果展示”四个关键词。
- **现场展台顺序：** 先用游戏组吸引停留，再用硬件小车展示“真实运动”，最后用软件座舱解释“数据如何变成智能”。
