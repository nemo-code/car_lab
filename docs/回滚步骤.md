# car_lab 回滚步骤

回滚是受控操作。生产环境执行前必须确认维护窗口、备份完整性、数据导出用途和恢复负责人；本文件不授权生产操作。

## 触发条件

出现权限越界、登录/审批不可用、受保护附件异常、数据关联错误、持续健康检查失败或无法解释的高危错误时，停止继续切换并进入回滚评估。

## 切换期间

1. 停止新入口写入，保留错误日志和当前版本标识。
2. 导出并核对切换期间新增的用户、申请、资源、公告和审计记录，保存为独立证据。
3. 不删除 PocketBase 数据目录，不直接用旧数据库覆盖新数据库。
4. 确认旧 Node 服务、旧 SQLite 一致性快照、旧媒体和旧 Nginx 配置均可读取。

## 恢复旧链路

1. 将 Nginx API 代理恢复到已验证的旧 Node 服务。
2. 恢复匹配的旧前端构建产物和旧服务配置。
3. 使用一致性 SQLite 快照恢复旧数据库；恢复前保留当前数据库副本。
4. 启动旧服务，检查健康接口、管理员登录、学生登录、申请状态和公开资源。
5. 复核旧媒体路径、静态页面和 HTTPS 响应头。

## 恢复 PocketBase 候选

只有在明确选择继续使用 PocketBase 时，才使用固定版本二进制和匹配的备份执行：

```sh
npm run pocketbase:restore -- <backup_dir> <pb_data> --replace
```

恢复前由清单校验 SHA-256 和目录内容；恢复后重新执行健康、权限、文件和迁移验证。`node scripts/rollback-check.mjs` 只证明临时目录的文件级恢复，不代表生产恢复完成。

## 回滚后记录

- 记录触发时间、版本、错误现象、导出范围和恢复快照。
- 记录新增数据如何保留、重放或人工核对。
- 在未完成根因分析和回归验证前，不重新切换正式流量。
