# 项目素材验收边界

当前默认运行路径是 Node/SQLite。项目目录中的历史图片、视频和成果文件引用会保留在
`projects.media/videos/files`，缺失的旧文件只作为元数据展示，不会生成可下载死链。

当前公开仓库素材盘点（来源为
`public/projects/xiaoxueqi-2026/showcase-site/data.json`）：9 个项目共有 35 个图片引用，35 个图片文件均在仓库内；另有 9 个视频引用和 25 个成果文件引用，对应原件不在仓库内。按用户 2026-10-18 确认，视频和成果文件以后台在线上传、发布和下线为验收范围，历史原件不再作为本地功能阻塞项；管理员可上线后逐项目补录，批量迁移历史媒体属于可选运维事项。仓库中独立存在的成果展视频未被项目数据指向，不自动归属给某个项目。

管理员在 `/admin` 的“项目成果”工作区可以为已保存的项目添加两类素材：

- 历史引用：保存 `legacy_path`，用于记录尚未迁移的旧视频或文档；路径必须位于公开成果目录且文件存在才能标记为 `available` 并发布，缺失引用只能保留为元数据。
- 受控上传：上传图片、视频或成果文件，文件写入数据库目录下的 `project-files/`。

在线补录路径：进入 `/admin` → “项目成果” → 编辑已有项目 → “受控项目素材”，选择“视频”或“成果文件”，将“来源”设为“上传文件”，添加文件后编辑该素材、勾选“对外发布”并保存。上传默认保持未发布；管理员可随后替换或下线。

上传文件单个不超过 30 MiB。图片允许 JPEG、PNG、WebP、GIF；视频允许 MP4、WebM、QuickTime；
成果文件沿用资源库的 PDF、Office、ZIP 和纯文本白名单。服务端会重新校验 MIME、文件名和大小，
前端的文件选择限制不构成权限边界。

公开接口只返回已发布项目中 `published=true` 且 `availability=available` 的素材。管理员接口
可以查看草稿、缺失和已下线记录；下线采用逻辑状态并写入审计日志，文件不会通过 Nginx 静态目录
暴露。替换上传文件会先写入新文件，数据库提交失败时清理临时文件，避免留下未登记附件。

PocketBase 目录目前仍是隔离候选实现，不代表生产切换。固定 0.40.5 二进制的空库运行验证已
覆盖 `project_assets` 集合、存在性校验后的 legacy 元数据、真实 multipart 上传、公开文件 URL、替换后取消
发布、重新发布、下线后的旧 URL 失效和项目下线隐藏；可用
`npm run verify:pocketbase-project-assets` 重跑。该命令内部只用临时超级管理员 Token 初始化
空库，业务项目写入使用独立的 `users.role=admin` Token；`verify:pocketbase-files` 同样要求
`POCKETBASE_BUSINESS_TOKEN`，不能把 `_superusers` Token 当作业务管理员凭据。Linux 二进制、
备份恢复和生产接入仍需单独核验与授权。
